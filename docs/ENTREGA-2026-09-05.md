# JoystickNights — fechamento do backlog

## Implementação

- Feed cronológico completo com destaques preservados e paginação navegável.
- URLs `/page/N/` em home, categorias, tags e autores; busca preserva filtros na query e permanece `noindex`.
- Canonical por página, redirect de `www`, 404 para páginas além do acervo e API padrão diretamente no CMS.
- Falhas de conexão/5xx têm tentativas limitadas, timeout e propagação nos dados críticos: não se convertem em 404 ou sitemap parcial. Comentários e recomendações são auxiliares.
- Busca compacta, categorias, plataforma, tipo editorial, sugestões nativas e mensagem distinta para indisponibilidade.
- Reviews com nota opcional, prós, contras, veredito, ficha técnica, transparência e `Review` JSON-LD. Nota ausente não é interpretada como zero.
- Indicadores de plataformas, análises/guias nas categorias, progresso de leitura, anterior/próxima. Sumário, compartilhamento, relacionados e galeria existentes foram preservados.
- Plugin 1.3: redirects do tema antigo, noindex, feeds/sitemaps desativados, admin/API/mídia preservados, contrato de reviews e filtros antes da paginação.
- Metadados ausentes de tipo/plataforma são preenchidos a partir das categorias existentes em lotes de 100 acessados por administrador. Não são criadas notas nem opiniões editoriais.
- Atualizações compatíveis de sanitize-html, js-yaml e browserslist; override postcss 8.5.26 preservado.

O CMS permite rastrear os redirects e o noindex. Bloquear todo o host no robots impediria o Google de ler essas instruções: [documentação oficial](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

## Evidência de produção antes da publicação

A auditoria `npm run audit:seo` encontrou 706 URLs no sitemap, com 42 respostas 404, registradas em `SEO-AUDIT-2026-09-05.json`. Duas matérias foram conferidas diretamente na API e continuam publicadas. Testes de regressão confirmam que o código novo serve essas duas URLs com HTTP 200 e canonical correto.

O CMS exibiu uma falha transitória de conexão com banco durante a sessão. A origem compartilhada continua exigindo monitoramento; limitar concorrência não substitui capacidade de hospedagem. O build agora usa dois workers e E2E usa dois workers.

## Operação

Backups operacionais e segredos não pertencem ao Git. Uma cópia exata do plugin 1.1 instalado foi preservada privadamente antes da atualização. Os segredos já usados pelo CMS são constantes no wp-config.php; os destinos públicos fixos da versão anterior foram preservados como padrão apenas no host cms.joysticknights.com.br.

O deploy da Hostinger deve acompanhar `main` antes da remoção da branch antiga de implantação. A sessão da Hostinger inicialmente pediu autenticação. A validação das URLs específicas do Search Console depende de acesso à propriedade; a auditoria pública não substitui o relatório privado de indexação.
